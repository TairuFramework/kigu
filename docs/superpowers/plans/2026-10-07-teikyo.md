> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Create the `teikyo` stack repo with five plugin packages on `@sozai/http-server`: `@teikyo/hozon`, `@teikyo/access`, `@teikyo/enkaku`, `@teikyo/rate-limit`, `@teikyo/oauth`, plus an integration test of the kumiai-hub deployment shape.

## Review Focus

- **The same DID in two forms** (`did:peer:4` long and short form) -- grants stored and checked must agree; normalise with `normalizeDID` on write and read, the same function enkaku applies to `iss`. Other DIDs pass through unchanged: `did:key` base58btc is case-sensitive, so no case folding. Test owned by Task 3.
- **A grant whose `expiresAt` is in the past at insert time** -- stored but never matches. Test owned by Task 3.
- **`enkakuPlugin` with `access.grants` but `requireAuth: false`** -- rejected at setup with a clear error (grants need verified identities). Test owned by Task 6.
- **Token with an `iss` naming no configured authorization server** -- 401 `invalid_token` without any network fetch. Test owned by Task 9.
- **SQLite file databases closed while a grant lookup is in flight during shutdown** -- cleanup order guarantees `'access:grants'` closes before `'hozon:db'`; the integration test exercises shutdown under load. Test owned by Task 10.

```ts
export type Grant = { subject: string; pattern: string; expiresAt: number | null; createdAt: number; createdBy: string }
export type GrantStore = {
  grant(params: { subject: string; pattern: string; createdBy: string; expiresAt?: number }): Promise<void>  // upsert on (subject, pattern)
  revoke(params: { subject: string; pattern?: string }): Promise<number>   // pattern omitted: all for subject; returns rows removed
  list(params?: { subject?: string }): Promise<Array<Grant>>
  activeGrants(subject: string, now: number): Promise<Array<Grant>>
  onChange(listener: (subject: string) => void): () => void              // called after each committed mutation
}
export const GRANT_STORE = 'teikyo-grants'
export const grantStoreDefinition: StoreDefinition<GrantTables, GrantStore>
export function patternMatches(pattern: string, procedure: string): boolean
export function patternsOverlap(a: string, b: string): boolean
export type GrantCacheParams = { store: GrantStore; ttlMs?: number; now?: () => number }   // ttlMs default 5000
export class GrantCache { constructor(params: GrantCacheParams); allows(subject: string, procedure: string): Promise<boolean> }
```

- Table `grants` (prefixed by hozon's `TablePrefixPlugin`): `subject` text not null, `pattern` text not null, `expires_at` bigint null (epoch ms), `created_at` bigint not null, `created_by` text not null; primary key `(subject, pattern)`; index `${tablePrefix}_grants_subject` on `subject`. Migration key `'0-init'`, following `hozon/packages/store-log/src/migrations.ts`.
- Subjects are stored and queried through `normalizeDID` from `@kokuin/token`. Patterns are validated with `assertValidPattern` from `@kokuin/capability` on `grant`.
- `patternMatches` must use the same matcher and argument order enkaku uses for access-rule keys (read the call site in `enkaku/packages/server/src/access-control.ts`, `hasPartsMatch`). `patternsOverlap(a, b)`: `true` if either is `'*'`; else strip a trailing `/*` from each to get its base, and return `patternMatches(a, baseOf(b)) || patternMatches(b, baseOf(a))`.
- `GrantCache`: per-subject entry `{ grants, expiresAt, generation }`. Entry expiry = `min(now + ttlMs, earliest non-null grant expiresAt)`. `onChange(subject)` bumps the subject's generation and deletes its entry. A refill records the generation at start and is discarded (not stored) if the generation changed before it finished. `allows` returns whether any active grant's pattern matches the procedure.
